# Contributing to GeoCourse

Thanks for helping. GeoCourse is a draft, so questions and real-world files are as useful as patches.

## Ways to help

- **Ride or write a file and report what breaks.** Open an issue with the file, or a minimal part of it, and what you expected.
- **Spec questions and changes.** Open an issue first, quoting the section. Say what a reader or writer would do differently. Normative changes need agreement in the issue before a pull request.
- **Registry names.** See [the registry page](registry/README.md#request-a-name).
- **Validator and test files.** Pull requests welcome. Every new rule check comes with an invalid test file.

## Rules for changes

- A draft version of the spec and schema (`spec/<version>/`, `schema/<version>/`) may change until it is declared released. After that it is frozen and fixes go into the next version; typos in non-normative text are the only exception.
- A new test file is generated by `scripts/make-tests.ts`, not written by hand, and listed in `manifest.json`. Run `npm run make-tests` then `npm test`.
- Keep the validator free of runtime dependencies.
- Every source file starts with an SPDX licence header.
- Add a line to [`CHANGELOG.md`](CHANGELOG.md) under "Unreleased".

## Process

GeoCourse is a **proposed open standard**: a public draft, free to implement, that anyone can comment on and change through the steps below. It is not run by a standards body, and none has endorsed it.

1. **Issue.** Every change to the spec, schema or registry starts as an issue at https://geocourse.org/feedback/.
2. **Agreement.** Normative changes need agreement in the issue before a pull request. The maintainer (Atropical) decides when there is no agreement, and says why in the issue.
3. **Pull request.** The change, its test files and a changelog line, linked to the issue.

**Versions.** The spec uses semantic versioning. Before 1.0, any minor version may break. From 1.0 on, a minor version only adds things a reader may ignore, a patch only fixes wording, and anything that breaks a file or a reader needs a new major version.

**Implementations.** List yours in the [Implementations table](README.md#implementations) by issue or pull request.

## Develop

```sh
npm install
npm test          # build, then run validator and schema against tests/0.1
npm run site      # build the site into _site/
```
